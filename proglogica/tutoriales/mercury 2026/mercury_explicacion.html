¿Cómo funciona Mercury?

Guía interactiva — Lenguajes de Programación · Universidad Nacional de Colombia

⚙️ El modelo lógico de Mercury

Mercury ejecuta programas como una búsqueda de pruebas lógicas. Dado un conjunto de hechos y reglas, el motor intenta demostrar que una consulta es verdadera.

Hay tres conceptos centrales que trabajan juntos:

📋 Hechos y Reglas (la base de conocimiento)
↓
🔍 Consulta del usuario
↓
⚡ Unificación + Backtracking
↓
✅ Respuesta: éxito (con sustituciones) o fallo

📌 Hechos

Son verdades absolutas del dominio. No tienen condiciones.

% Estos son hechos:
padre(tom, bob).    % tom es padre de bob
padre(bob, ann).    % bob es padre de ann
edad(tom, 60).      % tom tiene 60 años

📐 Reglas

Son verdades condicionales: "A es verdad SI B es verdad".

% Regla: X es abuelo de Z si X es padre de Y e Y es padre de Z
abuelo(X, Z) :-
    padre(X, Y),
    padre(Y, Z).

% Regla recursiva: X es ancestro de Z
ancestro(X, Z) :- padre(X, Z).
ancestro(X, Z) :-
    padre(X, Y),
    ancestro(Y, Z).

🔄 Backtracking automático

Cuando un camino falla, Mercury retrocede y prueba la siguiente alternativa. Es como explorar un árbol de decisiones automáticamente.

% Si pregunto: abuelo(tom, Q)?
% Mercury intenta:
%   padre(tom, Y) → Y = bob  ✓
%   padre(bob, Z) → Z = ann  ✓
%   Resultado: Q = ann  ✅

% Si hubiera más hijos de bob, Mercury los encontraría todos.

🔗 Unificación — el mecanismo central

La unificación es el proceso de hacer que dos términos sean idénticos mediante sustitución de variables. Es más poderosa que la simple igualdad de otros lenguajes.

💡 Unificación en pattern matching

Mercury usa unificación implícitamente para seleccionar qué cláusula ejecutar:

:- func describe(list(int)) = string.
describe([])      = "lista vacía".       % unifica con []
describe([_])     = "un elemento".       % unifica con [_]
describe([_,_|_]) = "dos o más".         % unifica con [_,_|_]

🏷️ Sistema de tipos estático

A diferencia de Prolog, Mercury verifica tipos en tiempo de compilación. Esto elimina una categoría entera de errores antes de ejecutar el programa.

% Tipos básicos del lenguaje
int        → 42, -7, 0
float      → 3.14, -0.5
char       → 'a', 'Z', '\n'
string     → "hola mundo"
bool       → yes, no (módulo bool)
list(T)    → [1,2,3], ["a","b"]

🧱 Tipos algebraicos (ADT)

Permiten definir estructuras de datos complejas con constructores:

:- type forma
    --->  circulo(float)
    ;     rectangulo(float, float)
    ;     triangulo(float, float, float).

:- type maybe(T)       % tipo genérico/polimórfico
    --->  yes(T)
    ;     no.

% Uso con pattern matching:
:- func area(forma) = float.
area(circulo(R))        = 3.14159 * R * R.
area(rectangulo(A, B)) = A * B.
area(triangulo(A,B,C))  = Area :- ... .

🎯 Modos — dirección del flujo de datos

Los modos indican qué argumentos son entradas y cuáles son salidas al llamar un predicado:

ModoSignificadoEjemplo
::inArgumento ya instanciado (entrada)sumar(3::in, 4::in, ...)
::outArgumento sin instanciar (salida)sumar(..., ..., R::out)
::diDestructive input — para I/OIO::di
::uoUnique output — para I/OIO::uo
:- pred sumar(int::in, int::in, int::out) is det.
sumar(A, B, C) :- C = A + B.

% El compilador verifica que:
% - A y B lleguen instanciados
% - C salga instanciado

🎲 Declaraciones de determinismo

Una de las características más únicas de Mercury: el programador declara cuántas soluciones puede tener un predicado, y el compilador lo verifica. Haz clic en cada tipo para ver detalles:

det
Exactamente 1 solución. Nunca falla.
semidet
0 o 1 soluciones. Puede fallar.
nondet
0 o más soluciones. No determinístico.
multi
1 o más soluciones. Siempre al menos una.
:- pred factorial(int::in, int::out) is det.
factorial(0, 1).
factorial(N, F) :- N > 0, factorial(N-1, F1), F = N * F1.
% Siempre produce exactamente un resultado.
% El compilador garantiza que no falla para N >= 0.
:- pred buscar_en_lista(int::in, list(int)::in) is semidet.
buscar_en_lista(X, [X|_]).
buscar_en_lista(X, [_|T]) :- buscar_en_lista(X, T).
% Éxito si X está en la lista, falla si no está.
% El caller debe manejar ambos casos con if-then-else.
:- pred miembro(int::out, list(int)::in) is nondet.
miembro(X, [X|_]).
miembro(X, [_|T]) :- miembro(X, T).
% Puede producir 0, 1 o múltiples soluciones vía backtracking.
% Para lista [1,2,3]: genera X=1, X=2, X=3 sucesivamente.
:- pred entre(int::in, int::in, int::out) is multi.
entre(Low, High, X) :-
    Low =< High,
    ( X = Low ; entre(Low+1, High, X) ).
% Siempre produce AL MENOS una solución (Low mismo).
% entre(1, 5, X) → X=1,2,3,4,5

🛡️ ¿Por qué importa el determinismo?

El compilador de Mercury verifica en tiempo de compilación que el determinismo declarado sea correcto. Esto significa:

SituaciónEn PrologEn Mercury

Llamar predicado nondet como si fuera detComportamiento impredecibleError en compilación

🔒 I/O completamente puro

En la mayoría de lenguajes, las operaciones de I/O son efectos secundarios que rompen la pureza funcional. Mercury resuelve esto pasando el estado del mundo como un argumento explícito.

📦 El tipo io.state

Cada operación de I/O recibe el estado del mundo actual y produce uno nuevo:

% Sin azúcar sintáctica (cómo funciona internamente):
:- pred main(io.state::di, io.state::uo) is det.
main(IO0, IO) :-
    io.write_string("Hola\n", IO0, IO1),    % IO0 → IO1
    io.write_string("Mundo\n", IO1, IO).    % IO1 → IO

% Con azúcar !IO (equivalente, más limpio):
main(!IO) :-
    io.write_string("Hola\n", !IO),
    io.write_string("Mundo\n", !IO).
Estado del mundo: IO₀
↓ io.write_string("Hola", IO₀, IO₁)
Estado del mundo: IO₁ (después de imprimir "Hola")
↓ io.write_string("Mundo", IO₁, IO₂)
Estado del mundo: IO₂ (después de imprimir "Mundo")

✅ Ventajas del I/O puro

PropiedadExplicación
Orden garantizadoLas operaciones de I/O se ejecutan en el orden exacto que aparecen en el código
Sin efectos ocultosUna función sin parámetro IO nunca puede hacer I/O accidentalmente
Razonamiento localSe puede entender una función solo mirando sus parámetros
TesteableLas funciones puras son triviales de probar unitariamente

📖 Ejemplo: leer y procesar entrada

main(!IO) :-
    io.write_string("¿Tu nombre? ", !IO),
    io.read_line_as_string(Resultado, !IO),
    (
        Resultado = ok(Nombre) % lectura exitosa
    ->
        io.format("Hola, %s!\n", [s(Nombre)], !IO)
    ;
        io.write_string("Error al leer\n", !IO)
    ).

📝 Código fuente (.m)

El programador escribe archivos con extensión .m. Cada archivo es un módulo con sección :- interface. e :- implementation.

Comando: mmc --make mi_programa

🔍 Análisis sintáctico (Parser)

El compilador lee el archivo y construye un Árbol de Sintaxis Abstracta (AST). Verifica que la sintaxis sea correcta y reconoce declaraciones, predicados y cláusulas.

🏷️ Verificación de tipos

Mercury infiere y verifica los tipos de todas las expresiones. Si hay incompatibilidades de tipo (p.ej., pasar un float donde se espera un int), el compilador lanza un error antes de ejecutar el programa.

📊 Análisis de modos y determinismo

Se verifican las declaraciones de modos (::in, ::out) y determinismo (det, semidet, etc.). El compilador comprueba que las cláusulas sean consistentes con lo declarado. Esta fase es única de Mercury.

⚙️ Generación de código C

Mercury transforma el código lógico a código C optimizado. Aplica optimizaciones como eliminación de llamadas de cola (tail call optimization), lo que hace que la recursión sea tan eficiente como un bucle.

🚀 Ejecutable nativo

GCC o Clang compila el código C a un binario nativo para la plataforma. El resultado tiene rendimiento comparable a programas escritos directamente en C — muy superior a Prolog interpretado.
